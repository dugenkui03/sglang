Qwen3.5 Decode 调用链复习

2026-10-09 · 当前 learn 分支 · A4 黑白打印版

主线：请求索引与页表 → QKV 计算 → KV 写入 → 按页读取并计算注意力。
范围：普通解码(Decode)、即时执行(Eager)、全注意力(Full Attention)与 FlashAttention 后端；QKV 展开 native 分支，缓存写入展开 CUDA JIT 分支。

1. 每轮 Decode：准备请求索引与页表

假设本批两个请求 A、B，page_size=2；此前已分配请求槽位 req_pool_indices=tensor([5,9])，形状(shape)为 [2]。Decode 复用这些请求槽位。

请求 / req slot本轮前的 KV 槽位本轮新槽位本轮后的 KV 槽位
A / 5[6,7]，长度 22，新分配页 1[6,7,2]，长度 3
B / 9[8]，长度 19，续用页 4[8,9]，长度 2
ScheduleBatch.prepare_for_decode()
    │
    ├─ ① alloc_for_decode()：分配本轮 KV 槽位
    │    → out_cache_loc = tensor([2, 9])，shape=[2]
    │    → ReqToTokenPool.write()：更新请求到 KV 槽位的映射
    │         ├─ req_to_token[5, 2] = 2
    │         └─ req_to_token[9, 1] = 9
    │
    └─ ② seq_lens + 1：tensor([2, 1]) → tensor([3, 2])

这一步只分配槽位、登记索引；本轮 K/V 数值在后续各层前向中计算并写入。随后 TpModelWorker.forward_batch_generation() → ForwardBatch.init_new() 传递请求编号和更新后的长度。

EagerRunner._execute_decode()
→ HybridLinearAttnBackend.init_forward_metadata()
→ FlashAttentionBackend.init_forward_metadata()
    │
    ├─ ① 用 req_pool_indices=[5,9] 选取 req_to_token 的两行
    │    → tensor([[6,7,2], [8,9,0]])，shape=[2,3]
    ├─ ② 每隔 page_size=2 取一个槽位，再整除 2
    │    → tensor([[6,2], [8,0]]) // 2
    │    → page_table = tensor([[3,1], [4,0]])，shape=[2,2]
    └─ ③ seq_lens.to(torch.int32)
         → cache_seqlens_int32 = tensor([3,2])，shape=[2]

req_to_token 是二维表：[请求槽位容量, 每个请求的 token 位置容量]；上图只展示所选两行的前三列。req_pool_indices、out_cache_loc、seq_lens 为 int64；映射表、页表和 cache_seqlens_int32 为 int32。这里的 Tensor 值保存在 GPU 显存，CPU 内存中可另有长度镜像。

A 按页 [3,1] 读取 3 个 token，定位到槽位 [6,7,2]；B 按页 [4] 读取 2 个 token，定位到 [8,9]。第二行页表末尾的 0 无效，由有效长度限定读取范围。公式：kv_index = page_table[b, t // page_size] * page_size + t % page_size；b 为本批请求下标，t 为请求内 token 位置，均从 0 开始。

2. 全注意力层：计算本轮 Q/K/V

输入 hidden_states 是当前层处理的隐藏向量。以下展开可逐步阅读的 native 准备分支，以及未量化线性层的 F.linear 分支。

Qwen3_5AttentionDecoderLayer.self_attention()
    │
    ├─ ① forward_prepare_native()：准备 Q/K/V
    │    │
    │    ├─ self.qkv_proj(hidden_states)：QKVParallelLinear 对象
    │    │    → ColumnParallelLinear.forward()：继承的 forward
    │    │    → UnquantizedLinearMethod.apply()
    │    │    → F.linear()：输入 × 权重转置，可加 bias
    │    ├─ split() / chunk()：拆出 Q、K、V 及可选 gate
    │    ├─ _apply_qk_norm() → GemmaRMSNorm：按头归一化 Q、K
    │    └─ self.rotary_emb(...)：旋转位置编码(RoPE)
    │
    ├─ ② RadixAttention.forward()
    │    → HybridLinearAttnBackend.forward()
    │    → HybridLinearAttnBackend.forward_decode()
    │    → FlashAttentionBackend.forward_decode()  ← 见第 3、4 部分
    │
    └─ ③ 可选 gate → self.o_proj(...)：输出投影回 hidden_size

CUDA 开启输出门控时，实际走 forward_prepare_cuda_fused()，融合部分准备步骤。Q/K 归一化发生在注意力分数计算之前；V 不经过这里的 Q/K 归一化。张量并行(Tensor Parallelism，TP)下，普通行并行 o_proj 后各卡对同一输出的贡献通常求和(all-reduce)。

3. 写入本轮 K/V：Python → C++ → GPU

两层缓存池分工：HybridLinearKVPool 解析写入位置、映射层编号；其中的 full_kv_pool（此分支为 MHATokenToKVPool）管理实际 K/V Tensor。

FlashAttentionBackend.forward_decode()
→ HybridLinearKVPool.set_kv_buffer()：解析槽位、映射层编号
→ MHATokenToKVPool.set_kv_buffer()：按需缩放、转换 dtype
→ MHATokenToKVPool._store_kv_layer()：选中当前层缓存
→ _set_kv_buffer_impl()：这里展开 CUDA JIT 写入分支
→ store_cache()
    │
    ├─ ① _jit_kvcache_module()：取得编译后的代码模块
    └─ ② module.store_cache()：Python → C++ 绑定
         → StoreKVCacheKernel<...>::run()：C++ 入口
         → LaunchKernel(...).enable_pdl(...)(...)：启动 GPU 内核
         → store_kvcache()：写入指定 GPU 显存槽位

这里的 module 是编译后的代码模块，不是 GPU 显存地址。store_kvcache() 根据 indices，把本轮新算出的多个 token 的 K/V 写入缓存。

4. 读取缓存视图，再执行注意力计算

先取得当前层整个缓存池的 Tensor 视图，再让注意力内核(kernel)按请求页表读取有效槽位。常规路径获取视图时不会把整层 K/V 搬到 CPU 内存；需要反量化的缓存分支可能执行额外计算。

FlashAttentionBackend.forward_decode()：写入本轮 K/V 之后
    │
    ├─ ① get_paged_mha_kv_cache()：取得当前层分页视图
    │    → HybridLinearKVPool.get_kv_buffer()
    │        │
    │        ├─ _wait_for_layer()：分层加载时等待缓存就绪
    │        ├─ _transfer_full_attention_id()：模型层号 → 缓存层号
    │        │    → 例如模型层 3、7，对应缓存层 0、1
    │        └─ MHATokenToKVPool.get_kv_buffer()
    │             ├─ get_key_buffer() → _get_key_buffer()
    │             └─ get_value_buffer() → _get_value_buffer()
    │    → view(...)：[缓存页数, page_size, 本卡头数, 每头维度]
    │
    ├─ ② q.contiguous().view(...)：整理 Q 的布局和形状
    │    → [本轮 token 数, 本卡 Q 头数, head_dim]
    │
    ├─ ③ flash_attn_with_kvcache()：实际读取 GPU 显存并计算
    │    → page_table + cache_seqlens：定位各请求有效 K/V
    │    → Q @ K.T → 缩放与掩码 → softmax → V 的加权和
    │
    └─ ④ o.view(...)：展平各头输出，返回给上层 o_proj

复习时重点区分

概念区别与含义
分配 KV 槽位 / 写入 KV前者确定存放位置；后者才把本轮 K/V 写入 GPU 显存。
获取引用 / 读取数据普通 getter 返回 Tensor 引用；注意力内核按页表读取 GPU 显存中的 K/V。
view(shape) / contiguous()前者共享底层存储并改变视图；后者在不连续时会复制整理，GPU Tensor 仍留在 GPU 显存中。
.to(dtype) / .view(dtype)前者转换数值表示；后者按新类型解释原有字节，须满足形状与步长等条件。
full_kv_pool / mamba_pool前者保存全注意力层逐 token 的 K/V；后者保存线性注意力层的卷积状态与递推状态。
Python 入口 / GPU 内核Python 负责调用；GPU 内核执行计算或数据读写。内核也可用 Triton 编写并编译生成。
