# 学习总结视频约定

- 先读本目录的 `README.md`、`workflow.md`、根目录的 `LEARN.md`、`快速学习.md` 和 `.cursor/rules/answer-style.mdc`，再确定本次总结范围。
- NOTE 每个视频制作任务必须先用 `scripts/task.py` 创建唯一任务目录 `tasks/<任务ID>/`，建立本任务的 `TASK.md`。任务执行文件记录用户要求、讨论结论、方案、步骤、进度、参数、产物、验证结果和待办；接续工作必须先读它。
- NOTE 课程、草稿、配音缓存、图片、字幕、视频及执行记录全部放在所属任务目录内；任务标识与课程标识保持一致。不同任务禁止共用输出目录、覆盖任务文件或把旧任务结论当作本次已确认方案。同一视频的修订可在原任务继续，新视频必须新建任务。
- NOTE `tasks/` 整个目录已被版本控制忽略，任务执行文件和产物不得提交，也不得强制添加。公共规则、脚本及通用模板可以进入版本控制；通用模型安装可以复用，任务内容和缓存不混用。
- 此前生成的 Scheduler 演示内容已作废并删除；后续相关总结须重新建立任务、讨论方案，不沿用旧稿、旧页面数量或旧制作进度。
- 已有学习文档不等于用户已经学完；按当前对话与学习进度选内容，不自动把后续章节纳入回顾，不自动更新进度为完成。
- NOTE 每次内容总结必须覆盖以下清单，并在讲稿与幻灯片中对应呈现：
  1. **用户要求与历史对话记录**：提炼本次目标、学习范围、已讨论的结论、用户疑问与纠正、当前进度；只保留与本次讲解有关的上下文，不逐字堆砌聊天记录。
  2. **核心实体**：介绍核心类及对象的职责、关键状态、继承关系（含父类与 Mixin）、组合与协作关系；区分“继承自”“持有”“调用”，没有相关继承时如实说明。
  3. **核心方法与简化实现**：说明入口、输入输出、关键条件与状态变化；用简化代码保留主要实现，标注省略分支，并关联真实源码。
  4. **数据流**：说明数据由谁产生、经过哪些对象或队列、在哪一步转换、交给谁处理；区分跨进程通信与进程内调用、消息列表与执行批次。
  5. **流程图**：展示处理顺序、分支与关键判断；按需要补充时序图和实体关系图。图中名称、步骤与简化代码及讲稿相互对应。
- 上述清单是固定内容要求，不要求机械地一项一页；每页围绕一个问题组织，保持专家带读源码的连贯讲解。
- NOTE 对象之间存在关系时，必须画出简化的数据流图、继承图或协作关系图，参考根目录 `快速学习.md`；不能只用互不连接的概念卡片代替。用有方向的连线与动作标签明确“创建或转换”“持有引用”“调用”“继承”，父类、组成组件和数据对象不能混为一类。允许省略次要字段、方法与分支，但须注明省略范围；复杂关系拆成多页。
- NOTE 用户主要观看幻灯片中的图和代码区，主图必须脱离补充文字也能独立读懂。组件、分发器、通道、队列、数据对象和方法优先写当前源码中的真实类名、字段名或方法名；中文职责作为补充说明，不能只写“接收组件”“类型分发器”“执行组件”等概念名。图中关键箭头也要写真实调用或消息类型。
- NOTE 制作图示时，优先复用根目录 `快速学习.md`、`user_guide_zh` 和相关源码同目录 Markdown 学习文档中的 Mermaid 图。以现有图的实体、连线、步骤与边界为底图，按本次范围适当简化；仍要回到当前源码核对，不能因文档已有图就跳过校验。只有现有图不能表达本页问题时，才新增图。
- NOTE 页面不固定为左侧文字、右侧图。短代码与局部关系可以左右排列；长流程图、完整时序图和全局图优先使用“上方大图、下方有序说明”，给图留出完整宽度。版式服务于图的可读性，不为保持模板而压缩或截断图。
- NOTE 左侧要点使用 `①②③④` 有序编号；右侧数据流、协作关系、继承关系和时序中的每条连线也必须显示序号。流程型图按数据流动顺序编号；关系型图按左侧职责编号，同一职责关联两条边时允许复用编号，使左右能够直接对照。
- 逐项核对当前源码；用仓库相对路径与类名、方法名记录 `sources`，不要沿用过期行号。修改已有文件前重新读取，避免覆盖用户正在改的注释。
- 按熟悉框架的讲解者标准组织内容：先定位职责，再解释核心实体、数据变化、执行条件与设计作用，配一个能串起链路的请求例子。避免逐字念页面，也不要只堆方法名。
- 每页只讲一个问题，通常围绕三至五个讲解要点展开；配音片段按完整句子或小逻辑拆分，片段数不受要点数量限制。每段建议 20–60 个汉字，讲清“进来什么、改变什么、交给谁、何时返回”，补足原因与易错点。
- NOTE 讲稿必须是包含必要英文术语、类名和方法名的中文口语稿，可直接朗读，表达自然、有衔接，像熟悉框架的人带读代码；不能把页面要点、路径、行号和“当前源码”列表冒充讲稿。源码依据另存 `source-index.md`，制作说明和节奏安排另存 `storyboard.md`。不另写纯英文讲稿；当前沿用已选定的中文男声。英文名称首次出现时结合职责解释，后文可用明确简称，不堆砌标识符。
- NOTE 在写稿阶段就按句子粒度组织配音：一个片段表达一句话或一个完整的小逻辑，在自然停顿处结束；不能机械地按字数切断英文术语、方法名或前后因果。必要时先改写长句再分段。
- NOTE 讲稿在每个配音片段前写 `<!-- tts:页ID:片段序号 -->` 标记，课程源文件的 `narration` 数组与这些片段一一对应。标记只用于切分和定位，不读入声音、不显示为字幕。生成时按明确片段拆分，不再凭固定字符数任意二次切割。
- NOTE 配音片段尽量并行生成。按本机处理器配额和内存设置工作进程与每进程线程数，每个进程复用一次加载的模型；不能简单把每个进程都设为全部核心。按原片段顺序拼接，而不是按完成顺序；复用有效缓存，失败只重试对应片段，字幕依据各段实际音频时长对齐。
- NOTE 先列出重点学过的方法，再按方法逐页展开，不能把多个核心方法挤成一页，也不能用九页之类固定的小模板限制内容。页数由学习范围与解释所需深度决定，概念、继承关系、数据流、完整时序和复盘也需要独立篇幅；不靠重复内容凑页。
- NOTE 任意相邻两页中至少有一页以真实源码或方法简化实现为主；关系图和流程图不能连续两页都没有源码锚点。奇数结尾的复盘页也要检查它与前一页组成的窗口。
- NOTE 制作前规划章节结构、各页教学问题、讲解顺序、逐页预计秒数及总分钟数，明确主线、展开、例子、停顿与回顾的节奏。复杂方法可拆多页，并在章节切换时衔接前后内容；预计时长按实际讲稿估算，配音后更新真实页时长与总时长，不能用延长静帧伪造讲解深度。
- 展示核心方法时使用不超过十二行的简化代码，并显式标注主线路径与省略分支；保留真实方法名、关键条件和状态变化，不把伪代码冒充原文。
- NOTE 讲解方法时，代码块必须标明所属类，显示 `def 方法名(参数):` 与对应的简化方法体；保留必要的返回值和调用边界，不能只展示失去方法归属的匿名代码片段，也不能把调用者与被调用者的逻辑拼成一个方法。
- NOTE 代码图本身必须承担解释：在关键逻辑前加入 `# ①`、`# ②` 形式的简短中文注释，与本页要点按编号对应；高亮只标对应的注释或关键语句，不能出现无法从左侧要点解释的孤立深色行。即使观众不看左侧文字，也应能从方法签名、注释和关键语句理解输入、判断、状态变化与输出。
- NOTE 整套幻灯片使用柔和、统一的低反差浅色主题：米灰或浅绿背景，代码区沿用相近亮度的浅底，使用深灰绿文字和柔和高亮；禁止大面积深色代码块与亮色页面强烈对照，同时保证文字可读。
- NOTE 视频字幕统一使用红色文字和浅色描边；抽帧检查字幕颜色、对比度和遮挡情况。
- NOTE 幻灯片顶部只保留课程标识、页码和简短页标题；页面底部不显示源码路径、章节名、合成状态或时间段。源码位置保存到独立 `source-index.md`，章节节奏保存到 `storyboard.md`。删除底部重复信息后扩大正文、源码和图示区域，同时继续为视频字幕保留安全区。
- 图示只画本次需要的层次；不把条件路径画成必然路径。图中自定义步骤需说明层级；沿用源码 `【Step n】` 时保持对应。
- 区分接收消息列表、待调度请求集合和执行批次；生成请求入队后的结果异步产生，不能画成生成处理器同步返回最终答案。
- 复用 `run.sh` 和 `scripts/`；默认本机配音后端为 OmniVoice。Audio8 在本机验证不合格，不能因为模型更小便默认采用；不另起临时脚本绕过工作流。
- 当前用户要求并行协作；内容核对、幻灯片设计与配音测试可以并行，请另一 agent 复核关键概念和路径边界后吸收结论。
- 完整示例保留丰富讲稿；用 `--limit-slides` 做短样片时，必须指定独立 `--output-dir`，不能混同完整版本。
- 用户已试听并确认成熟低音男声，后续直接沿用 `male, middle-aged, low pitch`、十六步、速度 `0.95`。用户要求换声时先交付短句或短样片，按反馈调整后再全量生成。不要把波形有效与非静音当作专家讲解听感验收。
- 本机处理器并行总预算按八线程规划，多工作进程时分配每进程线程数，不能每个进程都占满八线程。声音配置见运行目录的 `quick_summary_voice.json`；新安装默认使用已确认的男声，重跑安装保留现有配置，只使用模型支持的标签，当前验证结论见 `VALIDATION.md`。
- 先生成并检查幻灯片，再生成配音与视频。检查术语读音、漏读、重复、截断、画面遮挡、字幕和切页；不能试听时如实说明，不能只凭命令成功宣称听感合格。
- 重建会把既有成片、全片和逐页合成音轨、字幕、切页清单及主要记录保存在 `previous/<时间>/`，保留逐段配音缓存。交付前看本次 `manifest.json` 的状态，不把历史成片或音轨当成本次成功结果。
- 保留课程源文件、来源、讲稿、口语稿、配音、字幕和图片；交付可直接打开的视频，并说明验证结果与未验证部分。
- 不自动提交、不清理用户原有文件；提交前遵守用户的确认要求。
