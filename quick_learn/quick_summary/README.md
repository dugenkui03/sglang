# 学习总结视频

- [制作流程图](workflow.md)：从已学源码和讨论记录，到幻灯片、男声讲解与字幕视频。
- 输入：已学过的一段源码、模块或概念，以及当前对话和学习进度。
- 输出：逐页幻灯片、包含英文术语的中文口语讲稿、章节节奏表、独立源码索引、中文配音、字幕和视频；每页时长跟随实际配音长度。
- 默认配音使用 OmniVoice 和用户已选定的成熟低音男声，在本机 CPU（Central Processing Unit）运行；首次安装需要下载依赖和模型，安装完成后的配音可离线运行。
- 旧 Scheduler 演示稿、扩写草稿及生成产物已按用户要求删除。后续总结重新建立任务并讨论方案。
- `build.py` 已接入句子级并行配音，本机双进程真实合成、缓存、片段顺序和单段重试已验证。默认两个工作进程各使用四个计算线程，复用各自加载的模型；系统辅助线程与计算线程预算分开记录。

## 1. 第一次运行

- 以下命令从仓库根目录执行；已有安装可以重复运行安装检查。

```bash
python quick_learn/quick_summary/scripts/setup_omnivoice.py
```

- 当前机器可复用已经安装的环境，避免重新下载：

```bash
python quick_learn/quick_summary/scripts/setup_omnivoice.py \
  --reuse-runtime ~/.local/share/sglang-narration/omnivoice \
  --threads 8
```

- 安装器支持 `--runtime-root` 指定新运行目录、`--reuse-runtime` 复用固定版本环境、`--font` 指定中文字体、`--threads` 设置默认线程数；先用 `--help` 查看当前接口。运行位置与解释器记录在 `config.local.json`，不要把本机绝对路径配置提交到仓库。
- 合成视频需要 FFmpeg，渲染需要中文字体。运行失败时先根据错误检查依赖；在 Debian / Ubuntu 上可使用系统软件包 `ffmpeg`、`fonts-noto-cjk`。
- 模型与实现来源：[OmniVoice 模型](https://huggingface.co/k2-fsa/OmniVoice)、[OmniVoice 项目](https://github.com/k2-fsa/OmniVoice)。同机也测试过 Audio8，但生成内容未通过本次验证，因此不作为默认后端。
- 本机默认八线程。当前男声短句实测用十六步采样、速度 `0.95`，约 15.66 秒生成 7 秒音频。该数字不代表整课耗时，线程对照、测量条件和试听状态见 [验证记录](VALIDATION.md)。
- 不需要启动 SGLang 服务，不需要云端语音密钥；中文夹杂代码名称的发音仍需试听。

### 先试听选声，再生成全片

- 用户已试听并确认采用成熟低音男声，后续总结直接沿用。用户希望更换声音时，先生成短句或少量页面，比较音色、语速、停顿和讲解感，再按反馈生成整课。
- 声音配置位于运行目录的 `quick_summary_voice.json`，例如当前机器的 `~/.local/share/sglang-narration/omnivoice/quick_summary_voice.json`。先读取现有配置，再修改需要的字段。

| 字段 | 作用 |
|---|---|
| `instruct` | 当前选定 `male, middle-aged, low pitch`；只能组合模型支持的标签 |
| `speed` | 当前选定 `0.95`；`1.0` 为基准，小于一更慢 |
| `num_step` | 生成步数，当前工作流使用 `16`；改变时需重新比较耗时和音质 |

- 当前本机配置和新安装默认值均为成熟低音男声、十六步、速度 `0.95`；重跑安装不会覆盖已经存在的声音配置。当前固定版本不接受 `warm`、`expressive` 这类自由情绪标签；讲解感还取决于口语表达、断句与强调顺序，不能只靠音色标签保证。
- 先按下一节建立任务，使 `SUMMARY_TASK` 指向该任务；下面的试听文件也只保存在该任务中。其他机器应使用 `config.local.json` 中记录的解释器和运行目录：

```bash
~/.local/share/sglang-narration/omnivoice/.venv/bin/python \
  quick_learn/quick_summary/scripts/speech.py \
  --runtime-dir ~/.local/share/sglang-narration/omnivoice \
  --threads 8 \
  --text "先抓住一个关键点：请求进入等待队列，只是获得调度资格，模型还没有开始计算。" \
  --output "$SUMMARY_TASK/outputs/voice-preview/sample.wav"
```

- 配置改变后会使配音缓存失效，后续构建重新生成相应音频。选声结束前保持在独立试听目录生成，避免反复重做整课。
- 波形非静音、时长合理、文件可播放，只说明技术检查通过；读音是否准确、有没有漏句，以及是否有专家讲解的节奏，必须听实际音频。

## 2. 每个视频一个任务执行文件

- 每个视频制作任务从独立的 `TASK.md` 开始，记录本次要求、讨论结论、方案、步骤、进度、参数、产物和验证；接续工作先读它。同一视频的修改继续使用原任务，新视频重新创建任务。
- 公共模板在 [templates/TASK.md](templates/TASK.md)。实际任务文件、课程、草稿、配音和视频全部位于 `tasks/<任务ID>/`，该目录整体排除在版本控制之外，不要强制添加。
- 即便名称相同，每次创建也会产生不同的时间戳和随机标识。创建只建立任务文件和空课程，不开始配音：

```bash
SUMMARY_TASK="$(python3 quick_learn/quick_summary/scripts/task.py \
  --name module-summary --title "模块学习总结" \
  --request "在这里记录本次总结的目标与范围")"
```

- 在新任务的 `TASK.md` 中整理方案，在 `lesson.json` 中填写课程；保留自动生成的课程 `id`。确定本次内容后执行：

```bash
bash quick_learn/quick_summary/run.sh "$SUMMARY_TASK/lesson.json" --slides-only
bash quick_learn/quick_summary/run.sh "$SUMMARY_TASK/lesson.json"
```

- 默认产物在本任务的 `outputs/full/`。短样片放本任务的 `outputs/preview/`：

```bash
bash quick_learn/quick_summary/run.sh "$SUMMARY_TASK/lesson.json" \
  --limit-slides 2 --output-dir "$SUMMARY_TASK/outputs/preview"
```

- 脚本检查任务与课程标识，拒绝跨任务写入；同一任务不允许两个构建进程同时修改记录。片段配音仍可以在同一次构建内部并行。
- `TASK.md` 的方案与人工记录由 agent 维护，自动执行区由构建脚本更新；`task.json` 记录任务身份、执行参数与历史，`manifest.json` 记录具体产物和时长。三者均仅属于本任务。
- 通用模型环境可以复用；不同任务的讲稿、来源、音频缓存和执行进度不得混用。

## 3. 每次总结的步骤

1. **确认范围**：读 [学习进度](../../LEARN.md)、[学习方法](../../快速学习.md)和本次对话，列清已经讲过的核心类、入口、数据对象、流程与易错点。现成文档用于参考，不作为“已经学过”的证明。
2. **核对源码**：重新打开相关方法，核对分支、返回对象与调用关系。每页在 `sources` 中保留文件路径和符号名；用户会同步修改注释，不沿用旧行号。
3. **规划并写课程**：在本任务的 `lesson.json` 中编写课程。先规划章节、逐页问题、预计时长和总分钟；重点学过的方法各自成页，复杂方法可以多页，不能压缩进固定的少量页面。每页一个问题，页面放重点，讲稿写成包含必要英文术语、类名和方法名的中文口语段落。
4. **检查幻灯片**：先用 `--slides-only` 渲染，打开 `contact-sheet.png` 和逐页图片，核对中文字体、箭头、方法名和代码高亮；文本放不下就拆页。
5. **检查配音**：沿用已确认的成熟低音男声，运行完整生成并抽查 `audio/` 中的逐段音频；更换声音时先让用户试听短句或短样片。长代码名可在 `spoken_text` 中改成易读的口头称呼，字幕与完整讲稿仍保留 `text`。
6. **检查成片**：打开 `video.mp4`，检查段落有无漏读、重复或截断，字幕是否遮挡，页切换是否与讲解一致。字幕按每段音频的真实时长对齐，不是逐字对齐。
7. **交付与保留**：提供视频及课程源文件的位置，说明本次学习范围、已检查项与未验证部分。保留全部生成材料，方便下次局部修改；不要自动提交，也不要自动把学习进度改为完成。

### 专家讲解标准

- **中文口播稿，保留英文术语**：用自然中文讲解，保留必要的英文术语、类名和方法名，包含例子与自然过渡；不另写纯英文稿。路径、行号和源码列表保存在单独索引，不混入讲稿。视频沿用已选定的中文男声。
- **篇幅与节奏**：先整理重点方法清单并各自安排页面，再补实体、关系图、数据流与复盘；页数按内容决定，不以九页或其他小模板封顶。安排章节顺序、每页预计秒数、总分钟和过渡，生成配音后校准实际时长。
- **源码密度**：任意相邻两页至少一页展示真实源码或带所属类的方法简化实现；概念图不能连续两页都没有源码锚点，结尾复盘页也与前一页一起检查。
- **固定内容清单**：用户要求与历史对话记录；核心实体（职责、关键状态、继承与组合关系）；核心方法及简化实现；数据流；流程图。按需补充时序图和实体关系图，不能用方法名列表代替说明。
- 历史对话只提炼与本次学习有关的目标、结论、疑问、纠正与进度。继承关系必须核对当前类声明，明确区分父类、Mixin、持有的组件和普通调用对象。
- 数据流要指出数据的生产者、对象形态、转换位置、经过的队列与消费者；流程图要体现顺序、关键条件和分支，并与简化代码及讲稿对应。
- **对象有关联就画连线**：参考 [快速学习.md](../../快速学习.md)，画简化的数据流、继承或协作关系图，不用孤立卡片代替关系。标清数据转换、持有、调用与继承的方向和含义；可以省略次要细节，关系复杂时拆页。
- **优先复用已有文档图**：先查 [快速学习.md](../../快速学习.md)、`user_guide_zh` 和相关源码同目录 Markdown 学习文档中的 Mermaid 图，以其实体、步骤和连线为底图做本次范围内的简化；再对照当前源码校验。现有图不能回答本页问题时才新增图。
- **主图使用源码术语**：主图和代码区按观众独立观看来设计。节点优先写真实类名、字段名和方法名，例如 `request_receiver: SchedulerRequestReceiver`、`_request_dispatcher: TypeBasedDispatcher`，再补中文职责；箭头写真实调用或消息类型，避免只写“组件”“分发器”“执行器”。
- **版式跟随内容**：局部关系和短代码可以左右排列；长流程、完整时序和全局图优先使用“上方大图、下方有序说明”。不为保持统一左右栏而压缩、截断或拆坏图。
- **左右编号对应**：左侧要点统一使用 `①②③④`；右侧关系图、数据流图和时序图的每条连线也显示序号。流程图按发生顺序编号，继承/组合图按左侧职责编号；一项职责对应多条边时复用同一编号。
- 先说方法在请求链路中的职责，再说明输入、状态变化、返回值与下游；说明从代码可见的设计作用，不猜测作者意图。
- 聚焦核心类和实体关系，串起一个普通请求的生命周期。正式页面通常围绕三至五个要点展开，配音片段按句子或完整小逻辑拆分；不能只复述画面重点。
- 核心方法用不超过十二行的简化代码展示，明确标注“简化”以及省略的分支；真实方法名、关键条件、入队与返回等状态变化应保留。
- 方法代码必须包含所属类、`def 方法名(参数):` 与简化方法体；不能只贴匿名方法体，也不能把多个方法拼成一个虚构方法。
- 代码区在关键逻辑前使用 `# ①`、`# ②` 中文注释，并与本页要点编号对应；柔和高亮只服务这些解释，不用无含义的深色行。代码区本身应能说明“进来什么、判断什么、改变什么、交给谁”。
- 统一使用柔和米灰、浅绿配色；代码区与页面保持相近亮度，采用深灰绿文字和柔和高亮，避免大面积深色代码块与浅色背景产生强烈反差，同时保证可读性。
- 视频字幕默认使用红色文字和浅色描边；从实际成片抽帧确认颜色、可读性和不遮挡页面主体。
- 页面顶部仅保留课程标识、页码与简短标题。源码路径、章节名和时间段不放在幻灯片底部，分别保存在 `source-index.md` 与 `storyboard.md`；腾出的空间用于放大源码和主图，最底部仍保留字幕安全区。
- 主线之外的分支用一句话标出边界，例如语法尚未准备好、队列达到上限、特殊部署切换队列；不要为了画面简洁把“可能”讲成“必然”。
- 请另一 agent 复核关键概念和链路边界，配音测试与内容核对并行。复核结论记录到本任务的 `TASK.md`。
- 教材中已有解释也要回到源码核对。注释发现歧义时，讲稿按实际逻辑修正，不直接改动用户正在编辑的源码。

## 4. 课程源文件

- 使用 JSON（JavaScript Object Notation）文件；`version` 固定为 `1`，实际文件位于本任务的 `lesson.json`。
- 顶层字段：`id` 必须保持为创建任务时分配的唯一任务标识，`title` 是课程标题，`subtitle` 是范围说明，`slides` 按播放顺序排列。
- 每页字段：

| 字段 | 用途与建议 |
|---|---|
| `id` | 唯一页名，修改页面时保留，便于定位 |
| `title` | 一句话点出本页问题或结论 |
| `section` | 所属章节，串起本页与上下游内容 |
| `estimated_seconds` | 本页预计讲解秒数，用于节奏表和全片预计时长；配音后另记实际值 |
| `bullets` | 一至六条，单条尽量不超过 45 个汉字；宽图页可在图下分栏排列 |
| `sources` | 来源数组，每项包含仓库相对 `path` 与 `symbol` |
| `visual` | 概念卡片、流程、时序、代码或本地图片，见下表 |
| `code_excerpt` | 可选源码旁注，含 `text` 与可选 `highlight_lines`；最多十二行，编号与本页说明对应 |
| `narration` | 讲稿段落数组，每项包含 `text`，可选 `spoken_text` |

- 每段讲稿建议 20–60 个汉字，保持一个完整意思；遇到长段落、长英文方法名或列表时拆段。`spoken_text` 可以替换读法，不能改变技术含义。
- 写稿阶段就按句子或完整小逻辑拆分，在每段前插入 `<!-- tts:页ID:片段序号 -->`；与课程源文件的 `narration` 元素一一对应。标记不参与配音和字幕，不能按固定字数切断术语或因果关系。
- 各片段尽量并行配音，每个工作进程只加载一次模型，并结合本机处理器配额限制每进程线程数；按讲稿顺序拼接，保留片段缓存和单独重试能力。
- 缩写在讲解文字中按仓库规则补英文全称；代码标识保持原样。避免整段逐字朗读代码，先在画面保留完整名称，再在口语稿中使用明确的短称。

| `visual.type` | 结构与限制 | 适合内容 |
|---|---|---|
| `relations` | `nodes: [{id,title,body?,x,y,w,h}]`，二至六个；`edges: [{from,to,label,kind,label_box?}]`；坐标为绘图区的零至一比例 | 数据转换、持有、调用及继承；`kind` 分别为 `flow`、`contains`、`calls`、`inherits`，用连线标明实际关系 |
| `cards` | `items: [{title, body}]`，一至四项 | 类、实体与职责对比 |
| `flow` | `steps: [{title, body}]`，二至四步 | 数据流、状态变化、处理流程 |
| `sequence` | `participants: [{id, label}]`，二至五个；`messages: [{from, to, label, return?}]`，一至六条 | 浅层调用、直接数据读写；`return: true` 标记返回 |
| `code` | `text` 最多十六行，`highlight_lines` 为从一开始的行号数组 | 核心条件、字段和方法骨架 |
| `image` | `path` 为相对课程源文件所在目录的本地图片路径，也可用绝对路径 | 既有科普图、复杂流程图或时序图 |

- 节点标题尽量不超过 20 个字符，说明不超过 45 个汉字，时序消息标签不超过 30 个字符。长方法名可在节点内简写，在页面重点和来源中保留完整名称。
- 页面可设置 `layout: "wide_visual"`，将主图放在上方全宽区域、说明放在下方分栏；该版式适合从现有 Markdown 图改编的全局流程与长时序。
- 复杂图建议另存可编辑源文件并导出图片，使用 `image` 引入；视频生成器不会执行图片中的图表源码。
- 讲解组织可按“链路位置 → 核心实体 → 核心步骤 → 请求例子 → 易错点”展开，根据实际学习范围增删；不要为了固定模板补进尚未学习的实现细节。

## 5. 运行选项

- `run.sh` 的相对课程路径按 `quick_learn/quick_summary/` 解析，也接受绝对路径；从仓库根目录执行时，传 `tasks/<任务ID>/lesson.json`。

| 参数 | 用途 |
|---|---|
| `--slides-only` | 只生成画面和讲稿，先检查排版 |
| `--limit-slides N` | 只生成前 N 页短样片；必须同时指定独立 `--output-dir` |
| `--threads 8` | 配音总计算线程预算，默认八；自动分给各工作进程，不能超过有效配额 |
| `--workers 2` | 配音工作进程数，默认二；默认配置为两个进程各四线程，模型各加载一次 |
| `--speech-retries 1` | 失败片段的额外重试次数，默认一；成功片段不重复生成 |
| `--force-audio` | 强制重生成配音；试听发现异常时使用 |
| `--output-dir PATH` | 只能指定本任务 outputs/ 内的独立子目录，使用绝对路径 |
| `--no-burn-subtitles` | 不把字幕烧入画面，仍保留独立字幕文件 |

- 修改讲稿、图片或排版后重新运行同一课程。构建开始时，已有的 `video.mp4`、`narration.wav`、`subtitles.srt`、`slides.ffconcat` 和 `audio/*-full.wav` 会移入 `previous/<时间>/`，同时备份当时已有的 `manifest.json`、`lesson.json`、`narration.md`；本次只渲染或失败后，不把这些历史成片、音轨或字幕误认为新结果。
- 逐段配音及其缓存记录保留在 `audio/`，满足当前讲稿、声音配置等签名时可以复用；逐页图片不保留完整版本历史。需要完全隔离的版本，仍使用不同的 `--output-dir`。交付以本次 `manifest.json` 记录为准，`slides_only`、`interrupted` 或 `failed` 都不代表新视频已完成。
- 并行生成时每完成一段就更新 `manifest.json`、任务 `task.json` 与 `TASK.md` 自动执行区；`speech` 内保留总段数、成功数、缓存数与逐段状态。中断后用原命令重跑，先校验讲稿、声音参数和音频内容散列，成功缓存复用，损坏或缺失片段重新提交。
- 并行片段可能先后乱序完成；音轨、字幕和切页始终按课程顺序与真实音频长度组装。普通失败重试复用原模型进程，只有进程异常退出时才重建；`--force-audio` 会主动跳过全部缓存，应仅在明确要重新配音时使用。
- 同时做多份总结时必须分别创建任务，独立维护执行文件和输出目录；配音会占用本机算力，适合与文档核对、幻灯片设计并行。

## 6. 输出文件

- 默认目录为 `quick_learn/quick_summary/tasks/<任务ID>/outputs/full/`；`--slides-only` 不生成音频与视频。

| 文件或目录 | 内容 |
|---|---|
| `slides/` | 逐页幻灯片图片 |
| `slides.pdf` | 可直接翻阅的整套幻灯片 |
| `contact-sheet.png` | 幻灯片总览，便于检查风格和版式 |
| `narration.md` | 含英文术语的中文口播稿及配音片段标记，不混入源码索引 |
| `source-index.md` | 按页列出的当前源码符号与行号 |
| `storyboard.md` | 章节、逐页重点、预计与实际时长 |
| `lesson.json` | 本次实际生成的课程快照；短样片只包含选中的页面 |
| `audio/` | 逐段配音，方便定位读音问题 |
| `narration.wav` | 全片配音，便于单独试听 |
| `subtitles.srt` | 按段落对齐的独立字幕 |
| `video.mp4` | 最终视频，默认带字幕 |
| `manifest.json` | 本次生成记录与时长等信息 |
| `previous/<时间>/` | 重建前的旧成片、合成音轨、字幕、切页清单及主要记录 |

- 本工具生成的是带旁白的逐页视频，图表以静态画面呈现；需要解释分步变化时，拆成连续多页。当前不生成可编辑的演示文稿文件，修改入口是课程源文件和本地素材。
- 模型的可用性、速度与音质以当前机器的实际验证结果为准，不从模型大小推断。质量以实际检查为准：脚本成功只说明文件生成完成，没有试听或没有完整播放的项目应在交付中注明。
