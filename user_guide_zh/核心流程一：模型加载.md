# 核心流程一：模型加载

`ModelRunner.load_model()` 在启动阶段组织模型创建和权重加载，随后把加载器、模型对象分别保存到 `self.loader`、`self.model`。本文以 `Qwen3_5ForConditionalGeneration` 的 embedding 权重为例，追踪“创建参数 → 保存加载方法 → 获取权重文件 → 填入参数”的过程。

下面对应 `DefaultModelLoader` 的普通启动加载路径，未启用 `is_startup_weight_load_overlap`。图中展开的是 embedding 分支；模型的其他层也会在初始化时创建各自的参数，再加载实际权重。使用 PP 时，embedding 位于第一个 PP 阶段。

```text
ModelRunner.__init__()
  → ModelRunner.initialize()
  → ModelRunner.load_model()
  → load_model_with_memory_saver()
  → DefaultModelLoader.load_model()
      │
      ├─ ① _initialize_model()：创建模型和参数
      │    → Qwen3_5ForConditionalGeneration.__init__()
      │    → Qwen3VLForConditionalGeneration.__init__()
      │    → Qwen3_5ForCausalLM.__init__()
      │    → VocabParallelEmbedding.__init__()
      │    → UnquantizedEmbeddingMethod.create_weights()
      │        ├─ 创建 weight，并注册到 embedding 层
      │        └─ 把 embedding 层的 weight_loader 保存到 weight 上
      │
      └─ ② load_weights_and_postprocess()：加载实际权重
           → Qwen3_5ForConditionalGeneration.load_weights()
           → 根据参数名找到之前创建的 weight
           → 取出 weight.weight_loader 并执行
           → VocabParallelEmbedding.weight_loader()
           → 把文件中的权重数据拷贝进 weight
```

入口见 [ModelRunner.load_model()](../python/sglang/srt/model_executor/model_runner.py#L1164)，选择加载器的封装见 [load_model_with_memory_saver()](../python/sglang/srt/model_executor/model_runner_components/load_model_utils.py#L265)。上图的两个阶段在 [DefaultModelLoader.load_model()](../python/sglang/srt/model_loader/loader.py#L963) 中依次执行，核心逻辑如下（省略其他分支）：

```python
with set_default_torch_dtype(model_config.dtype):
    with target_device:
        # 创建模型对象、各个模块和参数空间。
        model = _initialize_model(model_config, self.load_config, quant_config)

    # weights 是生成器，在后续遍历时准备文件并提供权重张量。
    weights = self._get_all_weights(model_config, model)
    self.load_weights_and_postprocess(model, weights, target_device)
```

加载器和模型类在不同位置选择：

| 选择什么 | 主要依据 | 对应方法 |
|---|---|---|
| 权重加载器，例如 `DefaultModelLoader` | `LoadConfig.load_format`，通常来自 `--load-format`；部分量化配置也会影响选择 | [get_model_loader()](../python/sglang/srt/model_loader/loader.py) |
| 模型类，例如 `Qwen3_5ForConditionalGeneration` | `model_config.hf_config.architectures`，对应模型 `config.json` 的 `architectures` | [get_model_architecture()](../python/sglang/srt/model_loader/utils.py#L197) |

`_initialize_model()` 取得模型类后执行 `model_class(**kwargs)`，进入上图的构造链。`Qwen3VLForConditionalGeneration.__init__()` 使用传入的 `language_model_cls` 创建内部文本模型；对这里的 Dense Qwen3.5 而言，该类是 `Qwen3_5ForCausalLM`。

**创建参数时，怎样保存 embedding 的加载方法？**

[Qwen3_5ForCausalLM.__init__()](../python/sglang/srt/models/qwen3_5.py#L1430) 创建 `self.embed_tokens = VocabParallelEmbedding(...)`。随后，[VocabParallelEmbedding.__init__()](../python/sglang/srt/layers/vocab_parallel_embedding.py#L339) 调用：

```python
self.quant_method.create_weights(
    self,  # 当前 VocabParallelEmbedding 对象，在 create_weights 中叫 layer
    self.embedding_dim,
    [self.num_embeddings_per_partition],
    self.embedding_dim,
    self.num_embeddings_padded,
    params_dtype=params_dtype,
    weight_loader=self.weight_loader,  # 传入绑定到当前 embedding 对象的方法
)
```

这里的 Qwen3.5 embedding 构造没有传入 `quant_config`，因此使用 `UnquantizedEmbeddingMethod`。它的 [create_weights()](../python/sglang/srt/layers/quantization/unquant.py#L184) 中，核心代码是：

```python
weight = Parameter(
    torch.empty(
        sum(output_partition_sizes),
        input_size_per_partition,
        dtype=params_dtype,
    ),
    requires_grad=False,
)
set_weight_attrs(weight, {"input_dim": 1, "output_dim": 0})
layer.register_parameter("weight", weight)
set_weight_attrs(weight, extra_weight_attrs)
```

这几行依次创建参数空间、保存分片所需信息、把参数注册为 `layer.weight`，并给参数对象添加额外属性。`torch.empty()` 此时尚未填入 checkpoint 中训练好的权重。

传入的 `weight_loader` 被 `**extra_weight_attrs` 接收。[set_weight_attrs()](../python/sglang/srt/utils/common.py#L2383) 遍历字典并执行 `setattr(weight, key, value)`，因此保存效果等价于：

```python
embedding.weight.weight_loader = embedding.weight_loader
```

**属性挂在 `embedding.weight` 这个 Parameter 对象上。** 其中保存的方法已经绑定到原来的 embedding 对象，调用时仍能使用该对象的词表分片信息。传入和保存方法都不会立即执行它。

**权重文件在哪里下载，什么时候开始下载？**

普通 Hugging Face 路径如下：

```text
_get_all_weights(...)
  → _get_weights_iterator(...)
  → _prepare_weights(...)
  → download_weights_from_hf(...)
  → huggingface_hub.snapshot_download(...)
```

[_prepare_weights()](../python/sglang/srt/model_loader/loader.py#L471) 检查路径，选择所需文件格式，再调用 [download_weights_from_hf()](../python/sglang/srt/model_loader/weight_utils.py#L592)。后者优先复用有效缓存，需要下载时调用 `snapshot_download()`。本地目录直接使用已有文件。

[_get_all_weights()](../python/sglang/srt/model_loader/loader.py#L727) 是生成器函数。调用它只是创建生成器；在这条普通路径中，后续 `model.load_weights(weights)` 消费生成器时，才沿上述链路准备文件，并由文件迭代器提供 `(name, loaded_weight)`。

下载得到的是磁盘中的权重文件；读取文件得到权重张量；把张量数据填入模型参数则由各参数的加载方法完成。

**为什么 getattr 能找到对应的 embedding weight_loader？**

[load_weights_and_postprocess()](../python/sglang/srt/model_loader/loader.py#L1014) 调用 `model.load_weights(weights)`。这里的 `model` 是外层 `Qwen3_5ForConditionalGeneration` 对象，进入的是它的 [load_weights()](../python/sglang/srt/models/qwen3_5.py#L1955)。它遍历整个模型的参数，包含内部文本模型的 embedding 参数。

下面只保留 embedding 对应的核心逻辑，省略其他参数的特殊处理和筛选：

```python
params_dict = dict(self.named_parameters(remove_duplicate=False))

for name, loaded_weight in weights:
    # 将 checkpoint 中的名称转换为当前模型中的名称。
    if "language_model" in name:
        name = name.replace("model.language_model.", "model.")

    param = params_dict[name]
    weight_loader = getattr(param, "weight_loader", default_weight_loader)
    weight_loader(param, loaded_weight)
```

例如，`model.language_model.embed_tokens.weight` 转换后成为 `model.embed_tokens.weight`。在这个外层模型的 `load_weights()` 中：

```python
embedding = self.model.embed_tokens
param = params_dict["model.embed_tokens.weight"]

# 两种访问方式取得的是同一个 Parameter 对象。
assert param is embedding.weight
```

`named_parameters()` 提供的是已经注册的参数对象，`dict(...)` 保存这些对象的引用。因此，`param` 上仍然带着初始化时保存的 `weight_loader` 属性。

| 变量 | 实际内容 |
|---|---|
| `param` | 模型初始化时创建的 Parameter，已经绑定专用加载方法 |
| `loaded_weight` | 从 checkpoint 读取的权重张量，作为待拷贝的数据来源 |
| `weight_loader` | 从 `param` 上取出的绑定方法；属性不存在时才使用 `default_weight_loader` |

`getattr()` 只是读取已有属性。对于 embedding，这次调用效果等价于：

```python
embedding.weight_loader(embedding.weight, loaded_weight)
```

最后进入 [VocabParallelEmbedding.weight_loader()](../python/sglang/srt/layers/vocab_parallel_embedding.py#L452)。普通未预分片权重会先截取当前设备负责的词表范围，再写入参数；补齐部分置零：

```python
if not self.use_presharded_weights:
    loaded_weight = loaded_weight.narrow(output_dim, start_idx, shard_size)

param[: loaded_weight.shape[0]].data.copy_(loaded_weight)
param[loaded_weight.shape[0] :].data.fill_(0)
```

`load_weights_and_postprocess()` 随后还会执行适用的权重后处理，例如量化实现需要的格式整理。整个加载流程返回后，`ModelRunner.load_model()` 保存 `self.model = loaded.model`，后续前向计算复用这个模型对象及其权重。
